Installer binaries in the `latest` release:
- <a href={assetUrl('latest', 'installer_win.exe') ?? LATEST}><code>installer_win.exe</code></a> — Windows
- <a href={assetUrl('latest', 'installer_linux') ?? LATEST}><code>installer_linux</code></a> — Linux x86_64

- <a href={assetUrl('latest', 'installer_mac') ?? LATEST}><code>installer_mac</code></a> — macOS (universal: Intel + Apple Silicon)

Each binary ships with a `.sha256` sidecar, so you can verify the download before you run it.

:::note[About the dates]
Packages are **dated, not version-numbered**: every publish stamps each package with the date its
content last changed (`YYYY-MM-DD`, UTC). That is why `fx-folder` can show an older date than
`utils` — it simply has not changed since.
:::

## Finding out what you have installed

Both the installer and the updater tab show the same per-package dates and status. Open the updater
from the browser menu — next to each package's manual-download link it shows the date of the
currently published package, and **Up to date** means your installed copy matches it. Re-running the
installer shows the same per-package dates, plus each browser's Up to date / Update available status.

## Reverting to an earlier build

The `latest` release always holds the newest build of every file. Each past publish is also frozen
in a dated release — `installer-<date>` for the installer binaries and helpers, `core-<date>`
for the package zips. Pick a version in each dropdown to get its files: the newest entry of each
kind links through `tag/latest` (always the current build), older entries through their own frozen
tag.
